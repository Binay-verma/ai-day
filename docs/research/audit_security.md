# Security and production-readiness audit: explainable-edge-copilot

- **Target:** git HEAD `605d8ca` of `/home/claude/explainable-edge-copilot` (server v2: auth/RBAC, SQLite store, notifier, MQTT, cameras). The audited files (`server/app.py`, `io/sensors.py`, `service.py`, `cameras.py`, `pipeline.py`, `security.py`, `io/mqtt.py`, `storage.py`, `notify.py`, `static/app.js`) are byte-identical to the snapshot the probes ran against.
- **Method:** source review plus live probes: real uvicorn servers, FastAPI TestClient, Playwright/Chromium for XSS, and clean-venv CI reproductions on Python 3.10 and 3.11. No project files were modified.
- **Probe scripts:** `/tmp/claude-0/-home-claude/1a520e14-b6eb-5a1b-8d00-8ea8a0661398/scratchpad/audit_sec/` (`probe_wt.py`, `probe_wt2.py`, `probe_wt_race.py`, `chunked.py`, `xss_browser2.js`, `wt_server.py`).

Severity scale: **Critical**: silent loss of safety function, reachable by a low-privilege actor. **High**: false or suppressed alarms, credential leak, or an unauthenticated crash. **Medium**: hardening gap with a realistic abuse path. **Low**: defence in depth.

## Prioritised summary

**Fix before any pilot:**

1. **S1 (Critical):** a SensorHub dict race kills the camera thread, and nothing reports it. A single device-key holder triggered it in seconds, and so could a legitimate new sensor node coming online. After that `/healthz` and `/readyz` still return 200, so Docker never restarts the container and the area goes unmonitored. Fix: add a lock, wrap `_step()` in try/except, and make liveness check camera threads and frame age.
2. **S2 (High):** sensor identity is not bound to a zone, on HTTP or on MQTT (the payload `zone` overrides the topic ACL). One compromised ESP32 can trigger fire alarms or suppress them anywhere on campus. A false fire alert was demonstrated live.
3. **S3 (High):** chunked request bodies bypass the 64 KiB limit and are read before auth. One anonymous 300 MB request took RSS from 161 to 1091 MB, so two parallel requests should exceed the 2 GB container limit.
4. **S4 (High):** RTSP passwords leak to viewer role users, to SQLite, and to Slack/Teams/email whenever a camera goes offline.
5. **S5 (High):** repeated dismissals of a closed alert let one operator persistently raise the fire threshold from 0.20 to 0.995. Accept feedback only for open alerts and cap the threshold.

**Next:** S6 (atomic calibration writes; a corrupt file currently stops the service from booting), S7 (zone allowlist and per-camera frame payload), S8 (lockout and rate-limit keys behind a proxy), S9 (CI quality job fails on mypy, so no SBOM, provenance or image is produced).

**Hardening:** S10 to S13.

Overall, the v2 layer fixed every unauthenticated, XSS and NaN issue found at bc10a1c. The remaining risk is concentrated in the sensor-ingest trust model and thread safety, which are exactly where false or missed fire alarms come from.
